CO-181, CO-182 and CO-146: a code that wasn't valid on the date of service

Clearia · October 2026 · denial codes, read properly

Denial codes CO-181, CO-182 and CO-146 are the payer saying: "CO-181: Procedure code was invalid on the date of service. CO-182: Procedure modifier was invalid on the date of service. CO-146: Diagnosis was invalid for the date(s) of service reported." In short: A code on the claim was retired, not yet in effect, or incomplete on that date. Recoverable with a corrected claim that uses the code valid on the date of service.

Why these cluster after code updates

Code sets change on a calendar, and payers check every code against the date of service, not the date the claim was sent.

  • Diagnosis codes update every October 1. CMS posted the October 1, 2026 diagnosis update for encounters from October 1, 2026 through September 30, 2027, so the weeks after October 1 are when CO-146 tends to rise.
  • Procedure codes change every January 1, when the new CPT code set takes effect.
  • HCPCS codes, including many supply and drug codes, are updated quarterly, in January, April, July and October.

So a visit on September 28 billed in October with a brand-new code fails, and so does an October visit billed with a code that was retired on October 1.

What usually causes them

  • A system that wasn't updated. The practice management system or encoder still carries last year's code table.
  • A diagnosis billed short. Diagnosis codes are valid only at their full number of characters. A truncated code reads as invalid and comes back as CO-146.
  • A retired or mismatched modifier. A modifier that was deleted, or one that isn't valid with that procedure code on that date, comes back as CO-182. When the modifier and the procedure don't match: CO-4.
  • Claims held across the update. Charges entered before the switch and billed after it, or the reverse.

The fix

  1. Look up the code that was valid on the date of service, and confirm the record supports it.
  2. Send a corrected claim inside the payer's filing window. These rarely need an appeal. Timely filing, and the proof that beats a late-filing denial.
  3. Find the source. One of these is a typo. Twenty in a week is a code table or a template, and fixing it once stops the rest.

Is it recoverable?

Almost always, because the service was real and only the code was wrong for the date. The risk is time. These sit in work queues as "coding cleanup" while the filing window runs. When the diagnosis is valid but doesn't support the procedure: CO-11.

Source: the code descriptions on this page are quoted from the X12 Claim Adjustment Reason Code list, the standard code set every payer remittance uses.

Questions people ask about CO-181, CO-182 and CO-146

What does denial code CO-181 mean?

The payer says the procedure code on the claim wasn't valid on the date of service, usually because it was deleted, replaced, or not yet in effect.

Why do CO-146 denials rise in October?

Diagnosis codes are updated every October 1, and payers check each code against the date of service. Visits billed with retired codes after the switch, or with new codes before it, come back invalid.

Can a CO-182 be fixed without an appeal?

Usually, yes. Send a corrected claim with a modifier that was valid for that procedure on that date. An appeal is only needed if the payer's own code table is wrong.

Are these denials recoverable?

Almost always, with a corrected claim inside the payer's filing window, because the service was real and only the code was wrong for the date.
