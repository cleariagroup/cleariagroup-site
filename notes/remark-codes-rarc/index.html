Remark codes (RARCs), decoded: what each one means, what it pairs with, and the fix

Clearia · October 2026 · denial codes, read properly

A remark code (RARC) is the second code on a remittance line. The reason code (CARC) says what the payer did. The remark code says why, or what to fix. Find the remark code in the table below, read the reason code it's paired with, and you know whether the line needs a corrected claim, a record, or a payment dispute.

Billers usually meet a remark code the same way. A line comes back short or denied, the reason code is something generic like CO-16 or CO-96, and the only specific clue is a string like "N290" or "M80" sitting next to it. So you paste it into a search bar. This page is the answer we'd want to find: what the code means in plain terms, what it usually travels with, and what actually fixes it.

How remark codes pair with reason codes

Every adjusted line on an electronic remittance (the 835) carries three things. A group code (CO, PR, OA, PI) says who the amount belongs to. A reason code (CARC) says what happened to it. A remark code (RARC), when present, explains the reason code. Think of the reason code as the envelope and the remark code as the letter inside.

Some reason codes are close to empty without a remark. CARC 16 ("claim lacks information or has submission or billing errors") is the clearest case: the X12 code list requires at least one remark code that isn't an alert to go with it. CARC 96 (non-covered) and 97 (bundled) behave the same way in practice. The remark carries the real reason, which is why a CO-16 can't be worked without reading it.

Three more things worth knowing:

  • Where they sit. Line-level remarks ride in the LQ segment of the service-line loop. Claim-level remarks sit in the MOA segment on professional claims and MIA on institutional ones. Many practice management systems post the reason code and drop the remark. What each 835 field holds.
  • "Alert" codes are informational. A remark that begins with "Alert" tells you something; it doesn't adjust anything. The money moves on the reason code.
  • Who maintains them. CMS maintains the remark code list and X12 publishes it with the reason codes, updated several times a year. Commercial payers use the same list, though some apply codes more loosely than Medicare contractors do.

Three kinds of remark code, three different jobs

Once you've read a few hundred, remark codes sort into three piles. The pile decides the work.

  1. Fix and resubmit. N290, N382, N350, M51, MA130, N479, MA04, N657. Something on the claim was wrong or missing. Nobody needs to be persuaded. A corrected claim (replacement, frequency code 7) for anything that was adjudicated; a new original for anything rejected at the front end. A letter here just burns days.
  2. Send the record. M127, N115, N386, and many N130s. The payer wants proof that the service met a written policy. The appeal is the chart, organized around the policy's own criteria.
  3. Dispute the payment. N381, M15, M80, N19, M144, N525, M86. These are payer rules applied to a clean claim. Some are right. A good share aren't: the wrong bundle, a modifier the edit ignored, a global window counted wrong, a contract rate that wasn't loaded. These are where payment disputes are won.

Pile one is fast and cheap. Pile three is where the money is, because it's where a payer rule fires the same way on hundreds of lines.

Read the remark, then count it

One N381 on one line is a curiosity. Two hundred N381s from the same payer on the same visit code, all allowed at the same short amount, is a contract-loading problem. One fix stops it for every future claim, and the past lines go back in one dispute. The same goes for M80 on every E/M billed with a minor procedure. Same with M15 on one recurring code pair.

So the most useful report a billing team can run is a count: remark code by payer by month, with dollars. Most practice systems can't produce it, because the remark was never stored. The raw 835 files still have it. That's usually where we start.

What it means for your practice

Route every denial by its remark code, not just its reason code. It tells you whether the line needs a corrected claim, a record, or an argument, and choosing wrong costs weeks against a filing clock. Then look for remark codes that repeat. Repetition means a rule. A rule that's wrong is one dispute, not a thousand. That's the work our team does in Clearia's diagnostic, across underpayments, administrative denials and downcoding.

Questions people ask about remark codes

What is a remark code on a remittance?

A remittance advice remark code (RARC) is a short code that adds detail to a claim adjustment reason code (CARC). The CARC says what the payer did to the line; the RARC says why, or what is missing. CMS maintains the RARC list, and X12 publishes it alongside the reason codes.

What is the difference between a CARC and a RARC?

The CARC is the adjustment itself, like 16 (missing information) or 97 (bundled). The RARC is the explanation that rides with it, like N290 (rendering provider identifier missing or invalid). A CARC can stand alone. Most RARCs can't; they always travel with a CARC.

What does remark code N130 mean?

N130 tells you to consult the plan's benefit documents or guidelines for restrictions on the service. It points to a plan policy without naming it. Pull the policy, check whether the service met its criteria, and appeal with the record if it did.

What does MA130 mean on a Medicare remittance?

MA130 means the claim was returned as unprocessable because information was missing or invalid, so there are no appeal rights. Read the companion remark code to find the field, then submit a new, corrected claim inside the timely filing limit. Don't file a redetermination.

Can I appeal a denial based only on the remark code?

The remark code tells you which door to use. Data-error remarks like N290, N382 and MA130 call for a corrected or new claim, not an appeal. Policy and payment remarks like N130, N115 and N381 can support an appeal or a payment dispute when the record or the contract is on your side.
